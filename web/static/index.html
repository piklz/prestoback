Backup Encryption
Encrypts new backup archives at rest (AES-256-CTR + HMAC-SHA256). The passphrase below is used automatically for scheduled backups — but restoring always asks for it again, never uses this stored copy silently. Per-app overrides are on each app's Edit screen.
Encrypt new backups by default
There's no recovery if you lose this passphrase — encrypted archives become permanently unreadable. Store it somewhere other than this Pi.
Remote Backup Targets
Copies each finished backup to an off-box destination — the local copy on this Pi is never replaced or skipped, this is always an extra copy. Everything runs inside PrestoBack itself — no external tool to install. Mount is a folder already inside this container (e.g. an SMB/NFS share mounted on the host and bind-mounted in). SFTP connects directly over SSH to any NAS or Linux box that supports it (Synology, TrueNAS, QNAP, a plain server) — just a host, username, and password or key. S3-compatible connects directly to AWS S3, MinIO, Backblaze B2, Wasabi, or anything else speaking the S3 API. Google Drive/OneDrive/Dropbox aren't offered since those need an interactive browser login that doesn't fit a headless container.

How self-update works

Spawns a detached helper container via Docker socket

5
PrestoBack is back up in ~15s — config, backups, and compose ownership untouched

Remove Application
Remove this app from PrestoBack? Its schedule stops immediately.
💡 This app has backup archives on disk. By default they're kept — you can re-adopt them later from the Backups tab even after removing the app config.
Update Application
Pull the latest image for this app and recreate its container(s)?
💡 Recreating a container always restarts it — there's no way to apply a new image without a brief restart, typically a few seconds to a couple of minutes depending on image size and connection speed. This runs in the background; check Live activity on the Dashboard or Telegram (if configured) for progress.
Adopt Backup
Import Backup File
Upload a .tar.gz backup archive from your device (phone, tablet, laptop) to this PrestoBack instance. The file is uploaded via your browser and placed into backups/{app_id}/ on the Pi — exactly where PrestoBack expects its own archives to live.
Expected filename format: {appid}_{volumeslug}_{YYYYMMDD}_{HHMMSS}.tar.gz
Example: homebox_homebox-data_20260623_222239.tar.gz
PrestoBack reads the app ID from the filename automatically.
Apply Update
PrestoBack will stop and restart (~15–20s). Config and all backups are untouched — only the container is replaced.

After clicking Apply, the page will disconnect briefly. Wait ~20 seconds then refresh manually.

The helper container (prestoback-updater) will appear briefly in your container list — this is expected and it will remove itself automatically.
